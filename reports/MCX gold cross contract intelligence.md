# AURUM IQ wins by proving the gap is noise

AURUM IQ can be built from MCX daily Bhavcopy data. Its strongest finding will probably be that most of the "mispricing" between GOLDM, GOLDTEN, GOLDGUINEA and GOLDPETAL is contract design, not opportunity. Two terms can be computed in advance and already explain most of the raw gap. The first is a fixed **+40 bps purity shift** (999/995). The second is a **carry gap of about 9 bps for every 5 days** of expiry difference at Indian rates. Whatever is left is mostly stale settlement prints in thin contracts, and it then has to clear a round-trip cost of roughly **15–20 bps** on any pair that includes a small contract. The deck's framing ("prices cannot be compared by simple subtraction", "a clear no-edge answer when there is none") is therefore the right one, and the method should be built to defend it with numbers. The biggest practical risk is data access, not the quant work. mcxindia.com returned **HTTP 403 (Akamai "Access Denied")** to every scripted request during this research, including a browser-like POST to the JSON endpoint behind the Bhavcopy page. Three other facts the deck states are also contested in the sources: GOLDGUINEA's purity and quote unit, the request date format, and the exact expiry rules. With eight days to the 27 October demo, the order of work should be: secure the data, encode a point-in-time contract spec table, build the expiry-matched basis, and ship the cost-gated, walk-forward "no edge" report. Dashboard polish can wait until the 20–21 November finale.

## The Bhavcopy is easy to parse and hard to fetch

The MCX Bhavcopy page (https://www.mcxindia.com/market-data/bhavcopy) is backed by an ASP.NET page method, `POST https://www.mcxindia.com/backpage.aspx/GetDateWiseBhavCopy`. The JSON body is `{"Date":"YYYYMMDD","InstrumentName":"ALL|FUTCOM|FUTIDX|OPTCOM|OPTFUT"}`, and the rows come back under `d.Data` ([mcxlib](https://pypi.org/project/mcxlib/)). Community scrapers send `Content-Type: application/json`, `X-Requested-With: XMLHttpRequest`, an `Origin` and `Referer` of mcxindia.com, a desktop Chrome user agent and `sec-ch-ua`/`Sec-Fetch-*` headers. mcxpy adds a fallback that first GETs the home page to collect session cookies and then retries the POST ([mcxpy](https://pypi.org/project/mcxpy)). In this research's own first-hand test on 19 October 2026, that request pattern returned **403 Access Denied** from Akamai, and so did a plain GET of the Bhavcopy page with a cookie jar. The deck's line "No API key needed" ([deck p.4](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)) is true but misleading. No key is needed, but a naive script is blocked. mcxlib's own documentation warns that "MCX website changes can break functions without a new package release" and caps date-range history queries at 365 days ([mcxlib](https://pypi.org/project/mcxlib/)). mcxpy describes itself as experimental and "for educational purpose" ([mcxpy](https://pypi.org/project/mcxpy)).

The ingestion design should therefore be a fallback chain that records which path produced each file. The order is: direct httpx with cookie warm-up; mcxlib; Playwright headless Chromium driving the real page; and finally a **manual-upload path**. The deck already promises the manual path ("Load a Bhavcopy file", [deck p.5](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)), and it is the only one guaranteed to work on demo day. Other sources exist: `GetHistoricalDataDetails`, which takes date ranges of 365 days or less ([mcxlib](https://pypi.org/project/mcxlib/)); broker historical APIs (Zerodha Kite, Upstox, Dhan, Fyers); and TradingView continuous symbols such as `MCX:GOLDPETAL1!` ([TradingView](https://www.tradingview.com/symbols/MCX-GOLDPETAL1!/?contract=GOLDPETALZ2026)). Use them only for cross-checks, because the challenge is defined on Bhavcopy settlement data. No public Kaggle or GitHub archive of the full MCX gold Bhavcopy history was found. Store every raw response unmodified under its date and SHA-256 hash, so the backfill is collected once and can be replayed.

### Fields carry units that silently break normalization

mcxpy selects these fields from the response: `DateDisplay, InstrumentName, Symbol, ExpiryDate, OptionType, StrikePrice, Open, High, Low, Close, PreviousClose, Volume, VolumeInThousands, Value, OpenInterest`. It renames them in a way that shows **volume and OI are in lots and Value is in ₹ lakh** ([mcxpy](https://pypi.org/project/mcxpy)). MCX JSON returns `ExpiryDate` as DDMONYYYY (`"05JUN2026"`) and .NET timestamps as `"/Date(epoch-ms)/"` ([mcxlib tests](https://pypi.org/project/mcxlib/)). mcxpy parses dates with `format='mixed', dayfirst=True`, which is indirect evidence that row date formats are inconsistent ([mcxpy](https://pypi.org/project/mcxpy)). The challenge brief describes three quirks: requests in DD/MM/YYYY, responses in MM/DD/YYYY, and a holiday request returning the last trading day's data. **None of these could be verified**, and the scrapers actually send `YYYYMMDD`. The parser must therefore be defensive rather than assume any one convention. It should `.strip()` every symbol, parse ExpiryDate with `%d%b%Y`, and assert that the row date equals the requested date, which catches holiday re-serves. It should also reject a file that is byte-identical to the previous day's, drop duplicate (symbol, expiry, date) rows, and require settlement > 0, OI ≥ 0 and expiry ≥ trade date.

The `Value` field gives a self-check that the notes did not spell out but that follows directly from the units. If Value is in ₹ lakh and Volume is in lots, then the implied average traded price is `Value × 10⁵ / (Volume × lot_grams / quote_grams)`. That figure should sit close to Close for every contract. If GOLDGUINEA fails this check under the per-8 g assumption but passes under per-1 g, the data itself has answered the deck's most dangerous open question. A cheaper sanity check is the price level. A per-8 g GOLDGUINEA quote should be about **0.8× the GOLDTEN price**, and a per-1 g quote about 0.1× ([quant notes, derived from ICICI Direct](https://www.icicidirect.com/ilearn/commodity/articles/how-to-trade-gold-in-commodity-derivatives-market-in-india-1)).

### Close is a 30-minute VWAP, and thin contracts make it stale

MCXCCL computes the closing or daily settlement price as the **VWAP of trades in the last 30 minutes**. If fewer than 10 trades occur in that window, it uses the last 10 trades instead. This follows SEBI circular SEBI/HO/CDMRD/DNPMP/CIR/P/2021/9 ([MCXCCL](https://www.mcxccl.com/clearing-and-settlement/calculation-of-closing-price-daily-settlement-price), seen only as a search snippet because the page returned 403). It is not confirmed whether the Bhavcopy `Close` is this DSP, and the zero-trade fallback rule was never retrieved. For GOLDGUINEA, or a far-month GOLDTEN, the "last 10 trades" can reach back hours before the close, while GOLDM's settlement reflects the final 30 minutes. That time misalignment shows up as a cross-contract gap which then "reverts" the next day. **It is the single most likely source of fake alpha in this project.** On expiry day the final settlement price (DDR) replaces the close. For the 999 contracts the DDR is a domestic spot price for 10 g of 995 gold, polled at about 5 pm and scaled by 999/995 ([MCX Gold Petal spec](https://www.achiieversequitiesltd.com/wp-content/uploads/2019/04/gold-petal-october-2019-contract-onwards.pdf)).

### Liquidity is concentrated in GOLDM and the near month

Lot counts mislead. GOLDPETAL appears among MCX's most-active contracts, with about 255K lots on 2 April 2026 ([IIFL](https://www.indiainfoline.com/commodity/MCX/top-traded-volume)). At 1 g per lot, that is only about 255 kg of gold. A GOLDM snapshot shows 1,73,920 lots of volume and 51,221 OI ([Groww](https://groww.in/commodities/futures/mcx_goldm)), which is roughly 17 tonnes. GOLDGUINEA OI on 7 September 2026 was about **11,357 / 5,673 / 3,720 lots** across the September, October and November contracts ([INDmoney](https://www.indmoney.com/commodities/futures/gold-guinea)), which is under 100 kg even in the front month. Zerodha Varsity calls liquidity outside GOLD and GOLDM "quite bad" ([Zerodha Varsity](https://zerodha.com/varsity/chapter/gold-part-1/)). No GOLDTEN volume figures were found anywhere, so the team will have to measure them from its own Bhavcopy pull. The trading session runs 9:00 am to 11:30 pm (11:55 pm in US winter). Some Indian holidays close only the morning session, and Muhurat trading is on Sunday 8 November 2026 ([Jainam](https://www.jainam.in/mcx-holidays/)). The holiday calendar must therefore be MCX's own, not NSE equity's.

### History is short where it matters

GOLDTEN was announced by an MCX circular dated **18 March 2025** and began trading on **1 April 2025**. One Zerodha bulletin says 2 April "subject to readiness" ([HDFC Securities](https://www.hdfcsec.com/blog/details/the-golden-age-of-investment-mcx-launches-10-gram-gold-futures), [Zerodha](https://zerodha.com/marketintel/bulletin/408469/mcx-is-launching-gold-ten-10-gram-futures-contracts)). That leaves about 18 months, or roughly 380 trading days, of GOLDTEN history by today. Circular MCX/TRD/456/2025 raised the number of listed GOLDM, GOLDTEN, GOLDGUINEA and GOLDPETAL contracts **from 3 to 6, effective 22 September 2025** ([MarketScreener](https://www.marketscreener.com/news/multi-commodity-exchange-of-india-modification-in-launch-calendar-of-gold-mini-gold-ten-gold-gui-ce7d59d3d88bf32c)). The term structure therefore has twice as many nodes after that date as before it, and the spec table must be point-in-time. The deck's callout, "shared history is limited and must be checked first" ([deck p.2](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)), understates the problem. A 250-day training window leaves only two or three out-of-sample folds for any GOLDTEN pair. That is a statistical-power constraint the final report has to state openly.

## Five forces push normalized prices apart, and only one is mispricing

The contract table below reconciles the deck ([deck p.2](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)) with the external sources. Every contract ticks at ₹1 in its own quotation unit, so the value of one tick per lot varies by a factor of 1,000 across products ([Zerodha Varsity](https://zerodha.com/varsity/chapter/gold-part-1/), [Bhaav Brief](https://bhaavbrief.in/learn/mcx-gold-contracts)).

| Contract | Lot | Quote basis | Purity | Expiry rule | Tick value/lot | Fine g/lot |
|---|---|---|---|---|---|---|
| GOLD (reference) | 1 kg | ₹/10 g | 995 | 5th (prior working day if holiday), bimonthly | ₹100 | 995 |
| GOLDM | 100 g | ₹/10 g | 995 | 5th (prior working day), monthly | ₹10 | 99.5 |
| GOLDTEN | 10 g | ₹/10 g | 999 | last calendar day, or last business day | ₹1 | 9.99 |
| GOLDGUINEA | 8 g | ₹/8 g (**contested**: ICICI says 1 g) | 999 per deck; **995 per older MCX delivery records** | last calendar day | ₹0.80 | 7.992 or 7.96 |
| GOLDPETAL | 1 g | ₹/1 g | 999 | last calendar day | ₹0.10 | 0.999 |

**Purity** is the first and simplest force. IBJA polls 995 first and derives the 999 rate mechanically. On 18 September 2026 the AM fix was ₹1,53,658 for 999 and ₹1,53,043 for 995 per 10 g. That ratio is exactly 999/995 ([5paisa](https://www.5paisa.com/blog/gold-rate-today-18-sep-26), [IBJA methodology](https://ibjarates.com/pdf/spot-polling-mechanism/spot-polling-mechanism.pdf)). Indian exchange bullion specs pay a proportionate 999/995 premium when 999 gold is delivered against a 995 contract ([NSE bullion specs](https://www.nseindia.com/static/products-services/commodity-derivatives-contract-specifications-bullion)). The Gold Petal DDR also converts the 995 spot to 999 with that same factor ([MCX Gold Petal spec](https://www.achiieversequitiesltd.com/wp-content/uploads/2019/04/gold-petal-october-2019-contract-onwards.pdf)). The +40.2 bps purity shift is therefore set by the exchange's own settlement rules, not chosen by the model. If AURUM IQ skips it, every GOLDPETAL-vs-GOLDM comparison starts out 40 bps "rich".

**Expiry mismatch** matters more than purity because it changes over time. GOLD and GOLDM expire on the 5th, while the three 999 contracts expire at month-end ([ICICI Direct](https://www.icicidirect.com/ilearn/commodity/articles/how-to-trade-gold-in-commodity-derivatives-market-in-india-1)). Matching "December GOLDM" with "December GOLDTEN" puts about 25 days of carry between the legs, which is worth about **0.45%** at 6.5% a year. That spread shrinks mechanically as both contracts approach expiry, so a naive z-score reads the decay as mean reversion. Pairing GOLDM expiring on the 5th of month M+1 with the small contracts expiring at the end of month M cuts the gap to about 5 days, or roughly 9 bps. The residual can then be removed by interpolating along the curve. The month-end rule itself is inconsistent across sources. One GOLDTEN contract expired on **28 November 2025** because the 30th was a Sunday, which suggests a last-business-day rule ([Zerodha](https://zerodha.com/marketintel/bulletin/433706/mcx-precious-metals-expiry-november-2025)). The safe practice is to read expiry dates from the data's own ExpiryDate column and not compute them from a rule.

**Duty and parity** move every contract together but at different speeds. India's gold import duty went from 15% to 6% in July 2024 and back to **15% on 13 May 2026**. That day domestic futures jumped 7.2% and dealer discounts hit a record of up to **$207/oz** ([Reuters via Kitco](https://www.kitco.com/news/off-the-wire/2026-05-13/gold-discounts-india-breach-200ounce-record-amid-profit-taking)). By July the discount had eased to about $19/oz ([Reuters via Kitco](https://www.kitco.com/news/off-the-wire/2026-07-10/asia-gold-gold-discounts-india-deepen-volatility-hurts-demand)). Duty is a level shift common to all five contracts, so it cancels in a cross-contract spread. On shock days, though, the hedger-held 1 kg and GOLDM contracts plausibly reprice faster than retail-held GOLDPETAL. That makes 24 July 2024, 30 January 2026 (a 12% one-day crash) ([Univest](https://univest.in/blogs/gold-price-today-mcx-crash-june-24-2026)), the February 2026 margin hikes ([Business Today](https://www.businesstoday.in/amp/markets/story/gold-silver-mcx-nse-withdraw-additional-margins-on-gold-silver-futures-after-sharp-price-correction-516843-2026-02-18)) and 13 May 2026 natural event-study dates for the dashboard.

**Delivery mechanics and lifecycle** create the fourth force. All five contracts are compulsory or staggered delivery. Brokers force retail square-off days before expiry. In May 2026, Zerodha required GOLDM (expiring 5 June) to be closed by 2 June, GOLD by 29 May, and the 999 contracts (expiring 29 May) by 26 May ([Zerodha](https://zerodha.com/marketintel/bulletin/448097/mcx-precious-metals-expiry-may-2026)). A tender period also adds 5% margin on Gold Petal ([MCX Gold Petal spec](https://www.achiieversequitiesltd.com/wp-content/uploads/2019/04/gold-petal-october-2019-contract-onwards.pdf)). The last week of each small contract is therefore dominated by forced retail exits and collapsing OI. Delivery-based convergence trades are also unattractive to retail: GST of 3% applies on delivery and only GST-registered jewellers can reclaim it ([5paisa](https://www.5paisa.com/index.php/news/mcx-to-introduce-gold-ten-futures-contracts-starting-april-1)), and 995 and 999 bars are not interchangeable for delivery.

**Liquidity and participants** are the fifth force, and the source of most apparent dislocations. Studies of the E-mini against the full-size S&P 500 find that the liquid contract leads price discovery ([Kurov & Lasser 2004](https://www.cambridge.org/core/journals/journal-of-financial-and-quantitative-analysis/article/abs/price-dynamics-in-the-regular-and-emini-futures-markets/7DFA66D1DDCE701D5713CA6B92E18DF2), [Taylor 2011](https://ideas.repec.org/a/taf/apfiec/v21y2011i10p717-734.html)). On MCX that implies GOLDM leads and the small 999 contracts adjust with a lag, which appears on daily settlement data as a gap that closes the next day. The only practitioner evidence of a persistent gap is a TradingQnA post describing a ~150-point GOLD-vs-10×GOLDM gap that carried into expiry ([TradingQnA](https://tradingqna.com/t/arbitrage-between-gold-and-gold-mini-contract/26923)). That is anecdote, and **no academic study tests relative mispricing across MCX gold contract sizes**. The literature gap is real and gives the project an original-research angle.

## Normalize to fine grams, match expiries on the curve, and keep β fixed at one

The normalization is a single line per contract: `p_fine = P / quote_grams / fineness`. In ₹ per gram of fine gold this gives GOLDM `P/10/0.995`, GOLDTEN `P/10/0.999`, GOLDPETAL `P/1/0.999` and GOLDGUINEA `P/8/0.999`, with the GUINEA divisor and fineness both waiting on verification. For display, convert to "₹ per 10 g of 999", which multiplies GOLDM by 1.00402. The original price must stay in the row, as the deck promises ([deck p.3](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)). Work in logs, so that every spread is in basis points and the gold level cancels.

The term-structure step follows Koijen, Moskowitz, Pedersen and Vrugt (KMPV). They avoid unreliable spot data by interpolating futures to a constant maturity, and they use interpolated prices **only for signals, never for traded returns** ([Koijen et al. 2018](https://research-api.cbs.dk/ws/files/57294842/lasse_heje_pedersen_et_al_carry_acceptedmanuscript.pdf)). The steps are as follows. For each date, take every live contract with a valid, non-stale settlement and compute its time to expiry τ on ACT/365. Within GOLDM, compute the implied net carry between adjacent nodes, `c = ln(p_j/p_i)/(τ_j − τ_i)`. Read the GOLDM reference curve off at each small contract's exact expiry, `ln p̂_ref(τ_k) = ln p_i + c(τ_k − τ_i)`. The relative-value basis is then `B_k = [ln p_k − ln p̂_ref(τ_k)] × 10⁴` bps. Extrapolating beyond the GOLDM nodes must be flagged as lower quality. Implied carry c should be compared each day with an external benchmark such as MIBOR or the T-bill rate. A persistent gap between them is the price of financing and storage net of convenience yield, not an arbitrage. D.E. Shaw found the same for S&P futures, where implied financing ran at up to about 4× its recent average for most of 2024–25 ([D.E. Shaw](https://deshaw.com/assets/articles/DESCO_Imbalance_Sheet_20250123.pdf)).

For attribution, KMPV define carry as "an asset's futures return, assuming that prices stay the same" ([Koijen et al. 2018](https://research-api.cbs.dk/ws/files/57294842/lasse_heje_pedersen_et_al_carry_acceptedmanuscript.pdf)). Write a held contract's log price as level plus curve premium, `f_i(t) = s(t) + g_t(τ_i)`. Its daily change then splits exactly into three parts: the level move Δs; roll-down along today's unchanged curve, `g_t(τ_i − Δt) − g_t(τ_i)`; and the change in the curve at constant tenor. In a cross-product position the level move and most of the roll-down cancel. What remains is ΔB plus a residual, which arises because the reference legs actually held do not sit exactly at τ_k. That residual must be reported as its own line so that carry leakage from the expiry gap cannot pass for alpha. One more structural fact matters here. GOLDM and the 999 contracts **never share a delivery date**, so delivery never forces their basis to converge. Convergence comes only from arbitrageurs carrying one leg across dates, which brings in repo and FSP-polling risk.

The signal itself should not be estimated with Engle-Granger, Johansen or a Kalman hedge ratio. Contract terms fix the economic hedge at **β = 1 in fine grams**, and every estimated parameter is another way to overfit. Test the known spread for stationarity with ADF and KPSS, and estimate the half-life from an AR(1) fit, `HL = −ln 2 / ln φ`, which is valid only for 0 < φ < 1 ([ArbitrageLab](https://hudson-and-thames-arbitragelab.readthedocs-hosted.com/en/latest/technical/api/arbitragelab/optimal_mean_reversion/ou_model/index.html)). If the basis is non-stationary, report that as a finding (the structural premium is drifting) rather than switching to a time-varying β. A local-level Kalman filter is justified only to track a slowly moving equilibrium, for example while the GOLDTEN basis settled after launch ([QuantStart](https://www.quantstart.com/articles/Dynamic-Hedge-Ratio-Between-ETF-Pairs-Using-the-Kalman-Filter)). The deck's three detectors map onto this design: rolling z-score, percentile, and median/MAD ([deck p.3](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)). Compute each one only from data through t−1, `z_t = (B_t − m_{t−1})/s_{t−1}`, use MAD × 1.4826 as the robust scale, and set the window to 3–5× the half-life.

### Quiet alerts come from stacking gates, not from raising one threshold

"Quiet by default" is the design principle. An alert fires only if all of the following hold. The day's data trust score clears its bar. |z| ≥ 2–2.5. The dislocation in bps, times the expected reversion fraction, is at least 1.5–2× the round-trip cost. Both legs traded with non-zero volume on t and t−1, and neither settlement is unchanged from the prior day. The condition holds for two consecutive settlements. Neither leg is inside its broker cut-off or tender window. The pair is out of its per-pair cooldown. Re-arming also uses hysteresis: arm at |z| > 2, reset only below 1. A split-conformal variant calibrates the 1−α quantile of |B − m| on a held-out block, which bounds the false-alert rate at about α under exchangeability. A trade is also skipped if its half-life is longer than the days left to the earliest cut-off, since the spread cannot be expected to revert before the forced exit. On most days the digest should say so outright: "No actionable dislocation today: largest gap X bps, below cost hurdle Y bps." That sentence answers the deck's promise of "fewer false mispricing calls" ([deck p.5](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)).

## The backtest must trade real contracts, pay real costs, and try to kill its own edge

The timing protocol is simple. Decide on the settlement, volume and OI of day t. Fill at the **t+1 settlement plus slippage**. Hold explicit contract IDs (symbol plus expiry), mark them to market daily, and book rolls as explicit costed trades. No back-adjusted continuous series should appear anywhere on the P&L path, consistent with KMPV's split between signal prices and traded prices ([Koijen et al. 2018](https://research-api.cbs.dk/ws/files/57294842/lasse_heje_pedersen_et_al_carry_acceptedmanuscript.pdf)). The walk-forward scheme fits every parameter on a rolling 250-day window and tests on the next 20–60 days, then rolls forward. Trades that straddle a fold boundary should be purged. Every leg is flattened at the last settlement before min(broker cut-off, tender start − 1). Staggered delivery for the 999 contracts starts 5 days before expiry ([FYERS](https://fyers.in/notice-board/precious-metals-expiry-31st-october-2025-compulsory-delivery-contracts/)), so the GOLDM cut-off around the 2nd is usually the binding constraint. A custom loop of about 200 lines handles all of this more clearly than vectorbt. vectorbt's open-source 1.1.2 is Apache 2.0 with Commons Clause, and its futures multipliers and leverage are PRO-only ([vectorbt](https://pypi.org/project/vectorbt/)).

Lot matching is an integer problem with a fixed 0.4% residual. In fine grams, **1 GOLDM (99.5 g) ↔ 10 GOLDTEN (99.9 g) ↔ 100 GOLDPETAL (99.9 g)**, and the cleanest GOLDGUINEA unit is **2 GOLDM ↔ 25 GUINEA**. Each match leaves about 0.40% net gold exposure, which should be reported as a residual beta rather than hidden. The order cap of 10 kg per order on GOLDTEN and GOLDPETAL ([Angel One](https://www.angelone.in/news/commodities/gold-ten-futures-to-begin-trading-on-mcx-from-april-1)) never binds at these sizes.

### Costs decide the verdict before the statistics do

The cost stack for non-agri futures is as follows: CTT 0.01% on sells; MCX transaction charge 0.0021% per side (Zerodha's support page gives 0.0026% for group A, and the sources conflict); SEBI fee ₹10/crore; stamp duty 0.002% on buys; GST of 18% on brokerage, exchange and SEBI charges; and brokerage of **₹20 or 0.03% per order, whichever is lower** ([Zerodha charges](https://zerodha.com/charges/), [Zerodha support](https://support.zerodha.com/category/account-opening/charges-at-zerodha/articles/what-is-the-logic-behind-mcx-transactions-and-why-is-it-not-the-same-for-all-brokers)). The table below works these through at roughly ₹1.48 lakh per 10 g. The GOLDPETAL bid-ask spread is often ₹5–10 per lot ([Bhaav Brief](https://bhaavbrief.in/learn/mcx-gold-contracts)). The 0.03% cap means brokerage scales with notional on small orders, so splitting the order cannot reduce it. The GOLDM spread estimate is an inference, because no source quantified bid-ask spreads on GOLDM, GOLDTEN or GOLDGUINEA.

| Round trip, one leg | Statutory + GST | Brokerage | Bid-ask crossing | Approx. total |
|---|---|---|---|---|
| GOLDM (₹14.8 lakh notional) | ~1.7–2 bps | ~0.3 bps (₹20 × 2) | ~0.1–0.2 bps (inferred) | **~2–2.5 bps** |
| GOLDPETAL (₹14.8k notional) | ~1.7–2 bps | ~6 bps (0.03% × 2) | ~3.4–6.8 bps | **~11–15 bps** |
| GOLDM vs GOLDPETAL spread | | | | **~14–18 bps**, or a **25–35 bps** hurdle at k = 1.5–2 |

The hurdle is about the size of the purity shift. An un-normalized tool would therefore flag GOLDPETAL as "rich" on nearly every day, while a normalized, cost-gated tool will stay silent on most of them. That contrast makes a strong demo.

### Attribution and overfitting controls turn a null into a finding

Market neutrality has to be shown with data, not asserted. Regress daily strategy returns on front-month GOLDM returns, plus lags 1–2, which catch spurious lead-lag from stale small-contract prints. Use Newey-West standard errors. A neutral book should show |β| close to the residual 0.004 and an R² close to zero. Then come the multiple-testing controls. The **Deflated Sharpe Ratio** corrects for the number of configurations tried and for non-normal returns ([Bailey & López de Prado 2014](https://papers.ssrn.com/abstract=2460551)). **PBO via CSCV** estimates how often the in-sample best configuration finishes below the out-of-sample median ([Bailey et al.](https://papers.ssrn.com/abstract=2326253)). **White's Reality Check or Hansen's SPA**, run with a stationary bootstrap, tests the best rule against a flat book. The precedent is sobering: after correcting for data snooping, technical rules were profitable in only **2 of 17** US futures markets ([Park & Irwin](https://ageconsearch.umn.edu/record/19039/files/cp05pa01.pdf)). Harvey and Liu show that the right Sharpe haircut is nonlinear and falls hardest on marginal results ([Harvey & Liu](https://people.duke.edu/~charvey/Research/Published_Papers/P120_Backtesting.PDF)). Every grid point should be logged to an append-only `runs.parquet` so that the DSR trial count N is honest.

A rigorous "no edge" outcome has five parts. **Breakeven cost** is the mean gross P&L per round trip, with a bootstrap CI, and the verdict is "no edge" when its upper bound sits below actual cost. **Heatmaps** of net P&L over (z_in × z_out) and (z_in × cost multiplier 0–2) should show profit only near zero cost, not across a broad region. **Gross-edge attribution** splits P&L into stale-print reversion, expiry-gap carry leakage and residual; if the first two dominate, the edge is a measurement artifact. **Placebos** use random entries with the same holding-period distribution, shuffled signals, and a pure GOLDM front-vs-next calendar spread as a control. A **power statement** reports the minimum Sharpe the trade count could have detected. With GOLDTEN's roughly 380 days, that statement is what turns "not significant" into "we could have seen an edge of size X, and there was none."

## Contract lifecycle drives the calendar for the build itself

The live calendar during the build window gives the team a ready-made demo. The rules below are applied to the 2026 calendar; the dates must be confirmed against the ExpiryDate column and MCX's holiday circular. **31 October 2026 is a Saturday**, so the October GOLDTEN, GOLDGUINEA and GOLDPETAL contracts should expire on **Friday 30 October**. Their staggered-delivery window and broker cut-offs therefore fall around **23–26 October**, right as the demo is being recorded. GOLDM November expires **Thursday 5 November**, with a cut-off around 2 November. GOLDM December falls on Saturday 5 December and should move to Friday 4 December. The November month-end contracts expire **Monday 30 November**, so their tender window opens just after the **20–21 November finale**. The lifecycle Gantt can therefore show, on demo day, a contract going "no-trade" and the system declining to alert on it. Since September 2025, six contracts are listed per small product, so the curve has enough nodes for interpolation, but the far months will be thin. The spec table must be time-stamped: GOLDTEN starts 1 April 2025, the 3→6 listing change lands 22 September 2025, and later circulars can change tender lengths. ## Keep the deck's stack, but swap in DuckDB and a custom engine

The deck commits to Next.js, TypeScript, Recharts, FastAPI, pandas, NumPy, SciPy, "PostgreSQL or SQLite", pytest and Docker ([deck p.4](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)). The team has a dedicated frontend developer, and judges have already seen this stack, so the core should stay. Two choices should change. First, decide the open "PostgreSQL or SQLite" question in favour of **DuckDB over partitioned Parquet**. The data is a few thousand rows a year and needs no server. Use the raw → clean → features → results layers, with every row carrying `source_sha256`. Pin `duckdb==1.5.*`: 1.5.6 shipped on 28 September 2026, and the 2.0 release expected in October brings a new storage format ([DuckDB](https://duckdb.org/2026/09/28/announcing-duckdb-156)). Second, write the backtester as custom Python and do not adopt a framework. FastAPI should serve **precomputed JSON** per pair and date, so the frontend never waits on analytics. TradingView Lightweight Charts (Apache-2.0) suits the spread pane well if the attribution logo stays on ([lightweight-charts](https://bestofjs.org/projects/lightweight-charts)); Recharts covers the rest. If the Next.js build slips, a Streamlit page over the same Parquet files is a safe fallback for 27 October.

Ingestion runs from GitHub Actions cron at an off-the-hour minute. GitHub warns that jobs at the top of the hour may be delayed or dropped, and that public-repo schedules are auto-disabled after 60 days without activity ([GitHub Docs](https://docs.github.com/en/enterprise-cloud@latest/actions/monitoring-and-troubleshooting-workflows/troubleshooting-workflows/about-troubleshooting-workflows), [GitHub Docs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows)). The property tests should check that normalization agrees across units, that spread(A,B) = −spread(B,A), that costs are non-negative, that a zero signal produces zero P&L, and that truncating the data never changes past signals, which proves there is no look-ahead. ## Honesty is the moat, and the landscape gap is real but unproven

The deck twice admits that competitors are "not yet verified" ([deck p.5, p.7](file:///Users/himanshusolanki/Downloads/TimelessXO_Aurum.pdf)). The research supports a cautious claim. Public tools cover MCX-vs-COMEX parity, such as TradingView's "Silvara MCX-COMEX" indicator, which has duty as an input ([TradingView](https://it.tradingview.com/script/3Xm0bBc8-Silvara-Mcx-Comex/)), and sites like metalcharts ([metalcharts](https://metalcharts.org/india/xau)). Forum users discuss the classic GOLD vs 10×GOLDM trade ([TradingQnA](https://tradingqna.com/t/arbitrage-between-gold-and-gold-mini-contract/26923)). **No product was found that normalizes all five MCX gold contracts for purity, unit and expiry carry into one cross-contract monitor**, and no academic study tests that mispricing. This is absence of evidence: broker feature pages and GitHub were not searched exhaustively, and the GitHub connector failed during research. The deck should therefore say "we found no tool that…", not "the only tool".

No Hack in Hills rubric was found. Comparable fintech rubrics weight innovation, technical execution, real-world usefulness and presentation roughly equally. KSU gives presentation 20% ([KSU](https://www.kennesaw.edu/fintech/hackathon/fall-2025.php)), and Flow uses five equally weighted criteria ([Flow](https://flowhackathon.notion.site/Judging-Criteria-07b6cbeb99654a67aeb4ecfd88197dce)). Ranked by impact per build-hour, the differentiators are as follows. A **daily data-trust score** combines fetch path, date match, staleness and cross-contract ₹/g agreement, and gates every alert. **"Signal silence"** means a silence-streak counter and a stated reason for every non-alert. A **cost-breakeven map** plots pair against days-to-expiry with today's spread overlaid. The **lifecycle Gantt** shades each tender zone. A **research-integrity card** shows OOS Sharpe, DSR, PBO and a plain verdict. A **liquidity-haircut view** shows how much paper edge disappears at executable prices. The best demo story is a day on which GOLDPETAL looked rich in raw terms, AURUM IQ stayed quiet, and the next day showed it was right.

## Conclusion

The research changes what AURUM IQ is actually selling. The deck pitches anomaly detection. The evidence points to **anomaly explanation**: two computable terms (40 bps of purity and about 9 bps of carry per 5 days) plus one artifact (stale 10-trade VWAPs in thin contracts) should account for nearly all of the visible gap. The residual then has to clear a 25–35 bps cost hurdle that retail-sized contracts make hard to beat. A product that decomposes every rupee of gap into those parts, and stays silent when nothing is left, is more useful and more defensible than one that finds signals. Because no study covers this mispricing and no tool found does it, a well-documented null result is itself an original contribution.

The binding constraint is operational, not intellectual. Whether the 27 October demo shows real MCX numbers or a second synthetic chart depends on solving access in the next 48 hours and treating manual upload as a core path rather than a fallback. Everything else in the plan can slip a day; the data cannot.
